# Участие в разработке

Спасибо за интерес к Telegram Business Watcher. Небольшие, сфокусированные pull request проще проверить и безопаснее развернуть.

## Подготовка

```powershell
git clone https://github.com/<имя-пользователя>/telegram-business-watcher.git
cd telegram-business-watcher
npm ci
Copy-Item wrangler.example.jsonc wrangler.jsonc
```

Для модульных тестов настоящие Telegram- или Cloudflare-секреты не нужны.

## Рабочий процесс

1. Создайте отдельную ветку.
2. Внесите минимальное изменение.
3. Добавьте или обновите тесты.
4. Запустите проверки:

   ```powershell
   npm test
   npm run check
   npx wrangler deploy --dry-run --outdir .wrangler/dry-run --secrets-file .dev.vars.example
   ```

5. Проверьте diff на наличие секретов и персональных данных.
6. Откройте pull request с описанием поведения до и после изменения.

## Правила безопасности

- Никогда не коммитьте `.env`, `.dev.vars`, `wrangler.jsonc`, токены Telegram или Cloudflare.
- Не добавляйте в тестовые fixtures реальные сообщения, имена, chat ID или `file_id`.
- Не изменяйте уже опубликованные D1-миграции. Добавляйте новый последовательно пронумерованный SQL-файл.
- Не ослабляйте проверку webhook и административных маршрутов.
- Не копируйте защищённые, платные или обнаруженные автоудаляемые сообщения.
- Изменения криптографии должны сохранять аутентифицированное шифрование и иметь негативные тесты на неверный ключ или контекст.

## Стиль

- Используйте стандартные ES modules и Web APIs, доступные в Cloudflare Workers.
- Избегайте зависимостей, если задачу надёжно решает встроенный API.
- Сохраняйте понятные сообщения об ошибках без вывода секретов или содержимого сообщений.

Отправляя вклад, вы соглашаетесь распространять его на условиях лицензии MIT проекта.
