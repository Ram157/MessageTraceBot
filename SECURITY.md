# Политика безопасности

## Поддерживаемая версия

Исправления безопасности выпускаются для актуального состояния ветки `main`.

## Сообщение об уязвимости

Не создавайте публичный issue, если проблема может раскрыть:

- токены Telegram или Cloudflare;
- `SETUP_SECRET`, `WEBHOOK_SECRET` или `ENCRYPTION_KEY`;
- содержимое сообщений или персональные идентификаторы;
- способ обхода проверки webhook или административного доступа;
- возможность расшифровать, подменить или переставить записи D1.

Используйте **Security → Report a vulnerability** в репозитории GitHub, если включена приватная отправка отчётов. Иначе свяжитесь с владельцем репозитория по приватному каналу.

В отчёте укажите:

- затронутый файл или маршрут;
- минимальные шаги воспроизведения;
- ожидаемое влияние;
- безопасный вариант исправления, если он известен.

Не прикладывайте настоящие токены, ключи или содержимое личных сообщений. Используйте тестовые значения.

## Действия при утечке

1. Немедленно отзовите `BOT_TOKEN` через @BotFather.
2. Замените `WEBHOOK_SECRET` и повторно выполните `/setup`.
3. Замените `SETUP_SECRET`.
4. Отзовите затронутые Cloudflare API Tokens и проверьте журнал аккаунта.
5. Не заменяйте `ENCRYPTION_KEY` вслепую: сначала сохраните старый ключ и подготовьте миграцию ciphertext.
6. Удалите секрет из истории Git с помощью подходящего инструмента и считайте его скомпрометированным даже после удаления коммита.
